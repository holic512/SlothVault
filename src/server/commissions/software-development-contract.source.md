## 第七条 项目测试与验收

7.1 乙方完成约定开发内容后，应通过双方认可的方式向甲方发出验收通知，并提供测试地址、安装包或其他可验证成果。

7.2 甲方应在收到完整可测试成果及必要测试说明后的5个工作日内开展测试，并集中反馈问题。

7.3 验收依据包括：

（1）附件一确认的功能范围。

（2）双方确认的关键业务流程。

（3）约定运行环境中的功能表现。

（4）合同明确规定的其他验收指标。

7.4 验收问题分为：

**严重缺陷：** 约定核心业务流程无法完成、主要功能不可用，或者存在经验证的严重数据错误、严重安全漏洞等问题。

**一般缺陷：** 非核心功能异常、部分交互错误、兼容性问题或其他影响正常使用但不阻断核心业务的问题。

**轻微问题：** 不影响主要功能的文字、样式、提示信息或其他细节问题。

7.5 对于严重缺陷，乙方应合理优先修复，并在修复后重新提交相关部分测试。

7.6 对于一般缺陷和轻微问题，双方可约定修复清单及完成日期。对于不影响主要使用且双方同意后续修复的问题，可先进行附条件验收。

7.7 甲方反馈的问题应尽量包含具体操作步骤、预期结果、实际结果和必要的截图或错误信息，以便复现与处理。

7.8 甲方在验收期内既未提出具体异议，也未确认验收的，乙方应再次书面提醒，并给予不少于3个工作日的补充反馈期限。届满后仍无正当理由不反馈的，可视为约定功能通过验收，但不免除乙方对隐蔽缺陷、已知未修复问题和维护义务应承担的责任。

7.9 甲方将软件实际用于正式生产或商业运营的，可作为相应功能已经接受的重要验收证据，但不能当然证明所有功能均已验收合格。

7.10 验收不以甲方主观满意程度作为唯一标准，应以合同约定的客观要求为依据。

14.2 甲方未按约定付款的，经合理催告仍不履行，乙方可以暂停相应未履行义务，并要求支付到期款项。

14.3 对经核实属于乙方责任的延期交付，乙方应承担约定违约金：

每日按照延期部分对应合同价款的______%计算。

累计违约金上限：延期部分对应合同价款的______%。

14.4 建议双方根据项目规模、风险与损失情况填写合理比例；约定违约金依法可能受到调整。

14.5 甲方无正当理由拒绝提供必要协作、长期停止响应或拒绝履行付款义务，致使项目无法继续的，双方应就已完成工作量、已付款项及实际损失进行核算。

14.6 任一方违反保密义务、非法使用对方资料或侵犯知识产权的，应依法承担相应责任。

14.7 双方对损失及责任有争议的，应结合合同、需求记录、开发成果、付款凭证及其他证据确定。

14.8 双方可以就一般违约责任约定合理的责任上限，但该约定不得排除法律规定不得免除或限制的责任。

## 第十五条 合同变更、暂停与解除

15.1 合同履行过程中，任何一方均可提出变更，但应取得双方一致确认。

15.2 因甲方业务需求变化需要终止项目的，应及时书面通知乙方，双方根据已完成且可核实的开发工作、已发生的合理费用及依法应承担的责任进行结算。

15.3 因乙方原因导致项目无法继续或构成根本违约的，甲方可以依法要求补救、解除合同、退还相应款项或主张损失。

15.4 项目启动款及其他已支付款项不当然全部不予退还，也不当然全部退还，应根据实际履行情况、合同性质和法律规定处理。

15.5 合同解除时，双方应确认：

（1）已经完成的开发内容。

（2）甲方已经支付的费用。

（3）尚未支付或应退还的费用。

（4）阶段成果及知识产权处理方式。

（5）保密资料及账号权限处理方式。

15.6 因不可抗力影响合同履行的，受影响方应依法履行通知及证明义务，并采取合理措施减少损失。

15.7 合同解除不影响保密、争议解决、结算及其他依其性质应持续有效的条款。
