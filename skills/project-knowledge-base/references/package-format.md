# SlothVault knowledge package v1

`build-package.mjs` accepts one UTF-8 JSON file and generates a ZIP that SlothVault validates before importing. The builder and `validate-package.mjs` perform hard validation against this contract; neither command succeeds for a package outside these limits. The package contains:

```text
manifest.json
knowledge-base.json
articles/
  <article-slug>.md
```

`manifest.json` is generated by the script. Do not create it manually.

Both commands require the real inspected project directory:

```bash
node skills/project-knowledge-base/scripts/build-package.mjs \
  --input /absolute/path/knowledge-base.json \
  --source-root /absolute/path/inspected-project \
  --kind project \
  --output /absolute/path/project-knowledge.zip

node skills/project-knowledge-base/scripts/validate-package.mjs \
  /absolute/path/project-knowledge.zip \
  --source-root /absolute/path/inspected-project
```

## Source JSON

```json
{
  "project": {
    "name": "Project name from the inspected source",
    "description": "Optional, source-grounded positioning"
  },
  "knowledgeBase": {
    "title": "项目技术知识库",
    "summary": "A short description of the package"
  },
  "categories": [
    {
      "id": "architecture",
      "title": "架构设计",
      "order": 10,
      "articles": [
        {
          "id": "system-overview",
          "title": "系统整体架构",
          "slug": "system-overview",
          "summary": "面向读者的文章摘要",
          "articleType": "architecture",
          "tags": ["architecture", "backend"],
          "order": 10,
          "sourceReferences": [
            {
              "path": "src/server/bootstrap.ts",
              "symbol": "createServer",
              "kind": "source",
              "note": "服务装配入口"
            }
          ],
          "content": "# 系统整体架构\\n\\n正文 Markdown。"
        }
      ]
    }
  ]
}
```

## Import semantics

- A `project` package must contain one or more categories and articles. SlothVault creates the version entered by the administrator as a new draft, then imports the complete tree.
- An `article` package must contain exactly one category and one article. SlothVault appends it to a selected existing draft version; it reuses the category title when one already exists.
- `project.name` is descriptive evidence only. The administrator chooses the actual SlothVault project during import.
- Every article needs at least one `sourceReferences` entry. SlothVault stores those entries as structured JSON; they must identify real source paths and optional verified symbols, not invented implementation details.
- `content` is the authority imported into the editable Markdown document. The script copies it verbatim to `articles/<slug>.md`; SlothVault rejects the package if the mirror differs.

## Closed schema and hard limits

All root, project, knowledge-base, category, and article properties shown in the JSON example are required. The JSON must not include unknown properties. A source-reference object has required `path` and only optional `symbol`, `kind`, and `note` properties.

| Field / archive item | Requirement |
| --- | --- |
| Project name | 1–128 characters; description is required but may be empty, maximum 2,000 characters. |
| Knowledge-base title | 1–255 characters; summary is required but may be empty, maximum 2,000 characters. |
| Category ID / article ID | 1–128 characters. The first character is ASCII letter/digit; remaining characters may also be `.`, `_`, or `-`. IDs are globally unique. |
| Category title | 1–64 characters. |
| Slug | Lowercase ASCII words separated by `-`, 1–160 characters, globally unique. |
| Article title / summary / type | Title 1–255; summary required and may be empty, maximum 2,000; type 1–64 characters. |
| Tags | Required array with 0–30 unique items; every tag is 1–64 characters. |
| Source references | Required array with 1–500 items. `path` is 1–1,024 characters; `symbol` ≤ 512; `kind` ≤ 64; `note` ≤ 1,000. Present optional values cannot be empty. |
| Article content | Required, non-blank Markdown, ≤ 500,000 JavaScript characters and ≤ 2,000,000 UTF-8 bytes. Leading/trailing Markdown whitespace is allowed. |
| Orders | Non-negative integers up to 1,000,000. Category orders are unique globally; article orders are unique within their category. |
| Package cardinality | 1–100 categories and 1–500 articles. An `article` package has exactly one category and one article. |
| JSON / ZIP size | `knowledge-base.json` ≤ 32 MB; complete ZIP ≤ 250 MB; one ZIP entry ≤ 256 MB; total uncompressed data ≤ 1 GB; at most 10,000 entries. |

String metadata must not begin or end with whitespace. The builder does not silently trim it; correct the source JSON instead.

## Source-reference proof

`--source-root` is mandatory to package or validate. Every `sourceReferences[].path` must be a relative POSIX path below that directory:

- no absolute paths, Windows drive prefixes, backslashes, NUL bytes, empty segments, `.` segments, or `..` segments;
- the path must resolve to a readable regular file;
- if a symlink is involved, its resolved target must remain below the selected source root.

This proves that the cited source exists in the project inspected by the AI tool. It does not justify invented symbols or prose: include `symbol`, `kind`, and `note` only when they were verified in that source.

## Archive topology

The generated ZIP may contain only `manifest.json`, `knowledge-base.json`, the required `articles/<slug>.md` files, and an optional `articles/` directory entry. The validator rejects encrypted archives, unsafe paths, duplicate or conflicting paths, special files, unsupported compression methods, undeclared payloads, invalid UTF-8, hash/byte-count mismatches, and Markdown mirrors that differ from `content`.
