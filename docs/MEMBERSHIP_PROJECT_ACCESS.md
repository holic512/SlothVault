# 会员类型与项目阅读、下载权限

会员是可同时持有的独立类型。`rank` 只表示显示顺序，不表示类型间的继承关系。积分购买、授权流水和已有到期时间继续保留；同类型续费从当前时间与该类型最晚有效到期时间的较晚者计算。永久持有的同类型不会重复扣款。停售只停止新购买，既有有效授权仍参与匹配。

账户、用户管理及 MCP 读取返回 `activeMemberships`。同类型的有效授权合并，永久授权优先，否则使用最晚到期时间。`currentMembership`、购买响应中的 `membership` 及 `getEffectiveMembership` 保留为旧客户端兼容摘要，不能用于授权。

## 后台配置

项目编辑提供两个独立规则，项目内全部文档继承这两个规则。

| 规则 | 模式 | 条件 |
| --- | --- | --- |
| 阅读 | `PUBLIC` | 所有人可读 |
| 阅读 | `LOGIN` | 登录用户可读 |
| 阅读 | `MEMBERSHIPS` | 持有任一勾选的会员类型 |
| 下载 | `FOLLOW_READ` | 跟随阅读权限 |
| 下载 | `LOGIN` | 同时可读且已登录 |
| 下载 | `MEMBERSHIPS` | 同时可读且持有任一下载名单类型 |
| 下载 | `DISABLED` | 普通用户及访客不能下载 |

例如，阅读名单为 A、B、C，下载名单为 C，则 A/B 可在线阅读，C 可阅读和下载，未被勾选的 D 不因排序更大获得权限。同时持有 A、C 的用户可以下载。下载名单不能代替阅读名单；只有下载名单资格的用户仍不能读取或下载正文。

管理员保留管理预览和下载权限。会员模式必须至少选择一个存在的类型；停售类型在后台保留并显示状态。项目介绍、文档目录、已发布版本元数据及公开存证验证信息继续公开，锁定正文会解释登录或开通条件，可读但不可下载时显示下载条件。

管理员设置会员仅替换该类型。撤销请求必须传入 `membershipLevelId` 或显式 `all=true`，二者不能同时使用；网页撤销全部权益有独立确认。文章采用 `allowedMembershipLevelIds` 多选名单，空名单表示公开。网页 API 兼容 `requiredMembershipLevelId` 的单项写入；同时提交新旧两个字段会被拒绝。会员与内容权限由网页后台管理，MCP 只读取权限描述，文章内容工具不会修改允许名单。

## 文件与清单

`files_file_reference` 关联文件与正文、项目首页、菜单、文章、全站首页、头像及品牌配置，并区分 `READ_MEDIA` 和 `DOWNLOAD`。正文保存、发布、移动、恢复及数据库导入同步索引。历史回填只解析原文，不改写已发布正文，也不改变发布清单字节或哈希。

渲染托管链接时添加 `projectId`；附件链接同时添加 `download=1`。旧 `/uploads/...` 地址也经过文件记录和当前可见引用鉴权。图片展示使用阅读权限，图片的显式下载以及 PDF、源码、压缩包、Markdown 等文件使用下载权限。新上传、尚未绑定任何内容的文件仅管理员可访问。

同一文件可以被多个内容引用。旧地址按任一真实且当前可见的引用授权；指定 `projectId` 的地址只接受该项目真实引用并执行该项目规则。若另一项目或公开内容开放该文件，用户仍可通过该引用取得文件。请为不同开放范围上传不同附件副本。

系统生成的上传地址是根相对路径。若历史原文含完整的本站 URL，可以在构建及运行环境设置 `NEXT_PUBLIC_SITE_ORIGIN` 为本站规范源（例如 `https://docs.example.com`），然后执行索引回填或恢复。只有与该源相同的绝对 URL 被视为托管附件，其他站点链接保留原有行为。索引函数 `rebuildFileReferences` 在事务内重建引用，不读取或改写正文文件。

项目发布清单和文档存证清单包含完整正文，下载需通过下载权限。GET、HEAD 均在授权后才读取正文及处理 ETag；受保护响应，包括权限相关错误，使用 `Cache-Control: private, no-store`。项目介绍、目录和版本元数据可以共享缓存，但会员权益和权限判断每次读取数据库。

登录要求返回 401，会员不匹配或关闭下载返回 403，隐藏或不存在的内容返回 404。`verify-access` 返回 `canRead`、`canDownload`、两个拒绝原因和规则描述，旧 `hasAccess` 对应 `canRead`。

## 升级与备份

数据库修订号为 9，PostgreSQL、MySQL、SQLite 都包含 `20261008000000_parallel_membership_project_access` 迁移。部署后使用已有的安装/启动迁移流程升级，不应直接改写安装标记。升级顺序为 schema 迁移、历史文件引用回填、更新安装标记。

旧文章的等级阈值一次性转换成“旧要求等级及以上的所有现有类型”的允许名单，包含已停售类型，以保留旧访问范围。之后新增会员或调整顺序不会改变名单。旧项目默认 `PUBLIC` 阅读和 `FOLLOW_READ` 下载，保留现有公开范围。迁移不会撤销或延期已有会员授权。

数据库备份格式为 `2.8.0`，包含项目规则、文章允许名单和文件引用。导出校验关联闭合；恢复按新 ID 映射重建关联，并从实际原文重建引用。旧备份采用同样的文章名单转换和项目公开默认值。当前格式缺少权限字段时拒绝导入，避免把不完整备份默认成公开内容。

系统权限控制本站提供的正文及文件入口。浏览器已经取得的正文或图片、此前下载的文件无法收回；外部网盘及第三方链接不能由本站限制。

## 验证

定向覆盖会员购买与续费、管理员类型撤销、权限矩阵、Markdown/HTML 引用解析、上传 GET/HEAD、正文及两个清单路由、旧等级迁移、共享附件、2.8 备份恢复、旧备份转换、MCP 契约及发布哈希不变性。集成测试使用临时 SQLite 数据库，不访问安装中的业务数据库。

```bash
npm run prisma:validate
npm run typecheck
npm run lint
npm run lint:styles
npm run mcp:docs:check
```

生产构建使用独立的临时 `APP_DATA_PATH` 与 `UPLOAD_STORAGE_PATH`，避免构建加载安装状态时访问当前部署数据。PostgreSQL/MySQL 的 schema 和迁移脚本与 SQLite 保持一致；实际服务器迁移仍应在部署前的测试数据库演练。
