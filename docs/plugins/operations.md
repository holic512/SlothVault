# 插件安装、持久化与历史卡密退役

## 官方与手动安装

后台安装弹窗有两个入口：官方插件从内置 JSON 显示，再按插件 ID 查询应用 `vM.m.p` GitHub Release 中的源码 ZIP、选择版本、下载预览；手动安装上传源码 ZIP，高级选项可输入 GitHub owner/repository。源码包都通过同一校验、信任确认、编译及安装流程。

仅同时具有对应源码 ZIP 和 `checksums.sha256` 的稳定 Release 可安装；同一插件版本优先展示最新应用 Release，版本查询支持有界分页，查询失败不会伪装成无版本。没有完整 Release 时显示不可安装，不虚构远程版本，不从随应用的卡密 ZIP 自动安装。源码存在本地不意味着已安装。每次应用发布均附带全部插件，插件源码单独变更也触发应用新版本；旧 `v2.6.14` Release 不追补插件包，旧宿主需升级或使用可信源码 ZIP 手动安装。手动包即使使用官方 ID，也不等于来源已认证。

包兼容检查失败不能安装。编译失败保留旧版本；源文件、产物或恢复状态异常会明确报错，不能用启用或保存配置绕过恢复。默认新装禁用，启用才开放 API/菜单/页面；禁用保留业务数据。

## 持久化与清理

持久卷必须包含 APP_DATA_PATH，默认为 data。插件源码 ZIP、解包源码、编译缓存、临时文件、恢复快照分别位于 `plugins/{pluginId}/archives|packages|compiled|staging|snapshots`。插件配置、平台状态和业务表使用主数据库；不另起每插件数据库。

默认卸载保留表和配置；清理卸载需明确输入插件 ID，删除其自有表和插件文件，不回滚积分、不删宿主账本。旧升级快照只用于相符版本的恢复，不能反复套用覆盖后续业务。

## 一次性历史卡密退役

本站未投产，旧卡密明确废弃。宿主初始化插件前检查实际外键和表归属，删除固定历史卡密表及旧卡密专属平台记录，清理旧代码包和快照，再记录完成标志。非卡密表引用旧表时停止并报告，不级联删除。重复启动不会重复清理新卡密表。

当前工作区执行清理前的一致性 SQLite 备份位于 `data/backups/pre-source-plugins/before-retirement.sqlite`，权限 0600。该备份包含旧卡密和其他业务数据，仅用于人工恢复，不提交到 Git。

## 备份 2.18.0

新卡密通过通用 pluginRows/table descriptors 备份，不再导出专属 giftCards/giftCardBatches 集合。旧 2.13–2.17 备份仍可转换其余业务数据，但卡密集合和旧卡密安装/表/迁移/行会被丢弃，恢复预览提示 LEGACY_GIFT_CARDS_RETIRED；积分账本和金融幂等凭据不随之删除。

备份不执行源码，也不包含插件可执行安装包；恢复到其他机器后从可信 Release/源码 ZIP 重新安装代码。配置加密依赖原主密钥，主密钥丢失不回退明文。

## 部署限制

单实例运行；不得用 prisma db push/migrate dev 清理真实库中的插件表。生产镜像必须保留宿主编译 Worker、SDK 运行模块和 Rollup/TypeScript 依赖闭包，不能仅携带旧版业务 Worker。

MySQL 新站支撑索引补迁移仍保留，不修改已发布 SQL。依赖和运行边界通过生产构建与 standalone 验证；按本项目当前规则，不要求本地 Docker 镜像构建、体积或多架构验收，现有 CI 发布流程继续保留。
