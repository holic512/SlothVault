# 源码插件架构

## 边界

宿主是 Next.js App Router / React / Prisma，插件通过声明式 API、Service、事件、任务、菜单、页面与可选插槽扩展。独立插件源码在根目录 `plugins/`，不进入宿主业务源码目录。

默认推荐独立页面与菜单，只有确需补充原页面时使用插槽。卡密使用后台管理页面和账户兑换页面，不再注入积分中心或仪表盘。

## 安装与运行

源码 ZIP 经路径、文件数、解压字节、完整 SHA-256、Manifest 和入口映射校验后可预览。确认完整代码信任后，独立编译 Worker 以固定 Rollup/TypeScript 流程编译，不执行插件脚本、不下载依赖；编译并发为 1，60 秒超时。编译不占数据库维护锁。

编译成功才进入维护写锁，复核安装 generation、依赖、版本和表归属，执行迁移及生命周期健康检查，再提交版本指针。失败恢复前一版本。允许手动安装同版本新摘要，方便本地开发；重复相同包为修复，降级需明确回滚。

后台业务按需激活可终止 Worker，前端入口按贡献懒加载并共享宿主 React/Query/i18n/UI，不加载第二份 React。编译缓存以源码摘要、编译协议及宿主版本隔离，带主密钥认证的产物校验清单。缓存缺失从原信任源码重建，不重复建表迁移。

## 数据库

安装时宿主按表描述通过 Kysely 生成 SQL，使用现有 Prisma 连接执行；事务句柄仍由宿主绑定到调用。插件自有表不进入核心 Prisma 业务模型。核心 Prisma 只管理插件平台记录、用户、积分账本等宿主数据。

普通插件表使用 `svp_<插件ID摘要>_<逻辑表名>`；声明表归属和核心引用用于权限边界、账户归属及跨库备份。禁用不删表，卸载默认保留，明确清理才删除。不得使用 `prisma db push` 或 migrate dev 对真实站点清除插件表“漂移”。

旧卡密表与旧卡密安装状态已退役，不再接管或自动重装；新卡密使用同样的普通插件表，不设 legacyName 例外。

## 持久化

`APP_DATA_PATH/plugins/{pluginId}/` 保存源码归档、解包源码、编译缓存、临时目录和升级快照；整站恢复日志位于专用 `slothvault.restore` 子目录。默认根为 data，Docker 挂载 /app/data。安装状态、加密配置、任务与业务数据仍在主数据库。

Worker 是资源/异常隔离，不是恶意代码沙箱。管理员必须完全信任插件；哈希只证明文件一致，不证明作者可信。保持单实例部署边界，不提供任意 npm 依赖或宿主路由修改。
