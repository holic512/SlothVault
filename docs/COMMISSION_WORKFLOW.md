# 委托、合同与存证工作流

管理员从 `/admin/mm/commissions` 管理委托，从 `/admin/mm/contract-templates` 管理 Markdown 模板。用户从 `/account/commissions` 发起、确认和跟进委托。

## 使用流程

1. 建立委托草稿：管理员指定启用的普通用户，或生成有效期 7 天的一次性邀请；用户也可主动建立。附件上传后仅上传者可见。
2. 提交委托需求：正式提交冻结说明和选中的附件。管理员接单或说明原因退回；更正已提交内容须添加新记录。
3. 生成合同：选择已发布的模板，填写自动生成的字段和合同金额、确认方式、维护天数，关联需求与合同细则附件。
4. 发布固定版本：在线方式由所属用户阅读并确认或提出异议；线下方式由管理员上传依据并记录实际确认日期。未认领的委托不能发布正式合同。
5. 开始实施：合同确认后由管理员启动，可持续记录进展、阶段成果和需求补充。
6. 正式交付：必须包含至少一个“交付”用途的上传文件；可以另附外部链接。交付立即开始维护，默认 15 个自然日，网站按北京时间显示截止时刻。
7. 维护结束：用户可提前关闭；管理员关闭需写原因；服务每分钟检查到期委托，启动时补处理。关闭后不接收新问题，已有问题和处理记录保留。补充修复交付不自动延长期限。

用户支付比例为独立的 0—100% 整数，每次调整记录前后值；调低必须写原因。支付比例不会改变生命周期，结束委托也不会补齐为 100%。暂停为独立标记，暂停和终止都要求说明。

## Markdown 模板与版本

模板编辑器支持 `{{项目名称}}`、`{{委托方}}` 等中文、字母、数字和下划线变量，按首次出现顺序去重。默认文本框，可以配置多行文本、数字、金额、日期、选项、默认值和必填项；无变量的固定 Markdown 也可发布。

`项目名称`、`合同金额`、`维护天数`、`确认方式` 由委托业务设置提供。模板不执行表达式或代码。必填缺失会显示待填写提示，正式合同发布前必须补齐。

已发布模板不能覆盖，修改需创建新版本。合同单独保存模板版本、变量值和最终正文。合同补充协议需要再次走在线或线下确认流程；普通需求补充不会直接改动合同条款。

## 冻结与链上核验

每次正式事件保存稳定业务标识、序号、业务提交时间、操作者承诺、说明、业务数据、前序引用、文件原始字节 SHA-256 和上一事件摘要。快照采用键名排序、数组顺序保留的规范 JSON 编码，再对 UTF-8 字节计算 SHA-256。

应用提交后立即冻结。管理员在“文件与存证”中选择网络、连接钱包、查看手续费并签名。上链内容仅包含协议版本、随机业务标识、本次摘要和前序摘要；正文、文件名与用户资料不会写入链上。

Devnet 存证仅支持 Phantom，其他兼容钱包可使用其支持的 Mainnet 签名。准备交易显式设置计算预算和零优先费，签名时传入目标链并验证返回消息完全一致。确定的预检执行失败结束本次尝试并显示具体原因；广播结果不明时保留已签交易和原签名供对账。

状态区分已冻结待上链、待钱包签名、链上确认中、已存证、失败待重试。钱包取消、交易过期或网络异常均不撤销业务记录。已保存的签名交易由后台核对并重播相同字节；重新准备签名仍引用原快照。只有链上确认后才有可独立核验的外部摘要依据。

公共核验入口为 `/commission-evidence/[signature]`，不返回私有正文或附件。私有下载、合同发布和归档会校验文件字节。归档包含原始快照 JSON、文件及清单、合同正文、哈希链和链上回执信息。

## 升级、备份与测试数据

数据库修订号为 11，三种 provider 都包含 `20261009000000_commission_workflow`。旧记录保留 `workflowVersion=1`，作为只读历史；新建使用版本 2。启动升级仅初始化新模板，不再删除旧合同。备份格式为 2.11.0，恢复时重映射关系主键，保留快照 JSON 字节、稳定标识、摘要及签名交易。

本地 SQLite 测试数据有独立的一次性重建命令，不会在启动时执行。必须停止应用，明确指定经过确认的旧测试记录 ID；脚本拒绝包含合同或新流程记录的集合，并先备份数据库与关联附件。原文件元数据和字节全部保留，选中的委托重建为新流程草稿。

```bash
# 先检查限定集合；ID 仅为示例，必须替换为实际授权的旧测试记录。
node scripts/reset-commission-test-data.mjs --commissions=1,2 --templates=1
# 执行前先停止本地应用；备份路径由命令返回。
node scripts/reset-commission-test-data.mjs --commissions=1,2 --templates=1 --execute
```

该命令专用于本地 SQLite 测试数据。MySQL/PostgreSQL 正常升级会保留历史，不执行该清理命令。已有旧合同链上凭证继续使用原核验入口。

## 主要实现与验证入口

- `src/server/commissions/workflow.ts`：生命周期命令、权限、修订号与幂等。
- `src/server/commissions/submissions.ts`：冻结快照、附件校验和哈希链。
- `src/server/commissions/evidence.ts`：钱包交易准备、提交、重试与公共核验。
- `src/server/commissions/scheduler.ts`：维护到期处理及已签名交易核对。
- `src/server/commissions/workflow-backup.ts`：快照、合同与签名交易恢复校验。
- `src/server/commissions/workflow.test.ts`、`workflow-evidence.test.ts`：业务和存证目标测试。

MCP 保留委托列表、详情、建立草稿、编辑草稿、合同草稿和模板查询能力。已移除旧的通用进度覆盖命令；正式提交、确认及钱包签名通过网页明确操作完成。

旧合同创建、编辑、发起、取消、用户签署／拒绝，以及旧委托设置、文书草稿和旧合同新建存证接口已删除。历史合同读取、附件下载、原凭证核验和已提交交易对账继续保留。删除的路由不再作为兼容占位接口提供。
