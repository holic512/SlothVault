# SlothVault 正文 Manifest v2

项目版本的规范 JSON 为 `{"schema":2,"contents":["正文一","正文二"]}`。笔记正文的规范 JSON 为 `{"schema":2,"markdown":"Markdown 原文"}`。字段顺序固定，以紧凑 JSON 的 UTF-8 字节计算 SHA-256。下载文件、完整性校验和摘要响应头使用同一组字节。

项目版本收集未删除且启用的分类和笔记中的主正文。每篇启用笔记必须恰有一个未删除且启用的非空主正文。正文按 UTF-8 字节比较排序，重复正文保留；正文自身不做 trim、换行转换或 Unicode 归一化。Markdown 标题、图片地址和附件链接都属于正文。

项目名、头像、版本号、描述、分类名、笔记标题、正文版本说明、权重、数据库 ID、发布时间及发布 ID 不参与哈希。发布后允许修改名称、头像、描述、标题、正文版本说明和展示权重，修改后刷新展示缓存。实体 ID、发布 ID 和发布时间保留；正文集合和文档树的增删、移动、主正文切换及相关状态变更仍冻结。

`releaseId` 唯一标识发布记录；`releaseHash` 标识正文，相同正文允许多个发布记录。三种数据库均保留发布 ID 的唯一约束，移除哈希唯一约束。

数据库 revision 8 先执行 schema 迁移，再使用运行时同一实现重算旧发布记录，保留正文、实体 ID、发布 ID 和发布时间，最后推进安装标记。重算可重复执行。升级会检查凭证与尝试中的签名或提交记录；发现记录时以 `CONTENT_MANIFEST_UPGRADE_SIGNED_EVIDENCE` 和凭证 ID 停止。未签名的旧准备记录过期，需重新准备后签名。此部署以无既有上链记录为前提，不运行 v1 兼容分支。
