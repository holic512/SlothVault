# 委托与合同插件

`slothvault.commissions` 是委托、合同、模板与维护的唯一业务入口。使用宿主插件管理安装并启用发布包；宿主不再内置独立合同页面、委托表或旧路由兼容层。

## 使用流程

1. 在“委托列表”或“模板库”创建同一份需求草稿。管理员可立即准备合同；客户只提交需求，不需要钱包。
2. 提交需求时选择需求附件。内容冻结为待生效记录；管理员完成 **Solana 主网 FINALIZED** 存证后进入待接单。
3. 接单后选择模板、填写双方资料和业务条款、预览全文、选择合同附件，再发布。发布存证完成后才开放客户确认。
4. 客户在线确认，或管理员填写可追溯的线下确认依据。确认记录存证完成后合同在系统内生效；管理员链上签名不代表客户钱包签署。
5. 管理员启动实施，记录沟通和付款比例。正式交付时冻结说明与文件，存证完成即进入维护，不增加验收阶段。
6. 维护期限从交付首次生效的持久化时间开始。支持反馈、处理和说明原因的提前关闭；到期自动关闭无需额外钱包签名。

暂停独立于阶段；付款比例不推动阶段，也不会在结束时补成 100%。已有生效主合同可追加补充协议，但不覆盖旧合同。合同异议进入修订流程，不篡改历史版本。

## 界面与默认模板

管理端分为“委托列表”“模板库”“存证待办”，客户端提供“我的委托”。详情集中展示当前阶段、责任方、阻塞原因和下一操作；附件、版本及完整历史作为辅助区域。

首次安装幂等初始化八套场景模板：网站与后台、小程序与移动端、自动化数据处理、API 集成、部署迁移、技术支持、通用开发、变更补充协议。模板注明用途、前置条件和所需资料；补充协议不能用于无主合同的新委托。模板新版本不覆盖旧合同快照，已有草稿仍可读取所选的历史模板版本。

模板属于可编辑业务范本，不是通用法律适用性保证。客户与服务方信息、维护天数、项目名称等已知内容可自动带入；未知金额和业务条款须人工填写。

## 存证与文件安全

- 只有需求、合同发布、确认记录、正式交付四类节点强制存证，其余操作留存审计摘要链。
- 钱包拒签、余额不足、网络故障不丢失冻结内容；持久化签名后才广播，未知广播结果先核对同一交易，不重复创建业务动作。
- 未广播内容可以撤回；已提交签名必须先确认结果。客户端无权自行将阶段推进。
- 仅支持主网；无产品级测试网络、网络切换或客户钱包入口。
- 私有文件由宿主流式传输，插件判定归属和可见性。公开回执仅含摘要、交易及状态，不含正文、附件或客户资料。
- 所有写命令携带 `commandId` 与 `revision`，重复请求幂等、陈旧版本拒绝。

## 生命周期与数据

“暂停接新委托”不影响存量办理。插件正常停用关闭页面、公开回执、API 和任务；存在已广播待确认交易时禁止停用/卸载。重新启用进行对账与维护到期检查。保留数据卸载不删除合同或文件。

完整备份包含插件自有表与私有附件，恢复前检查归属、引用和内容摘要。可执行插件包不作为备份数据导入；按宿主插件恢复机制重新安装可信包。

不自动迁移历史宿主委托数据。三种数据库升级均先检查退休表为空；发现任何记录时拒绝迁移，不清空数据库或删除其他业务数据。含旧核心合同数据的备份也明确拒绝恢复，避免静默丢失。

## MCP

启用后动态注册 `slothvault.commissions.*` 查询与草稿工具。正式提交、合同发布、客户确认、签名和存证仍须网页完成；静态宿主 MCP 不再保留旧合同接口。

## 验证

目标测试：`npm test -- plugins/commissions/src src/server/plugins/mcp-commissions.test.ts`。

宿主集成：`npm run verify:plugins`，另运行备份恢复与退休表预检测试。SQLite 可本地隔离验证；MySQL/PostgreSQL 需专用测试 URL。自动测试使用模拟 RPC/钱包；真实主网签名和手续费须另行授权。
