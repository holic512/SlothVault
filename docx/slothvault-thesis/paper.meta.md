## 题目判断

本项目不是通用内容站点，而是一个围绕“项目-版本-分类-笔记”组织文档内容、并引入 Solana cNFT 进行项目访问验证的混合型文档管理平台。源码同时具备前台文档展示、后台管理、文件上传、系统首页配置、数据备份恢复、Merkle Tree 管理和压缩 NFT 铸造等能力，能够支撑“基于区块链的文档管理系统”这一毕业论文主题，但论文题目需要进一步聚焦到“压缩 NFT 权限控制”和“文档内容管理”两个核心特征。

综合 README、页面路由、API 和 Prisma 模型后，论文题目确定为“基于 Solana 压缩 NFT 的文档管理系统设计与实现”。这一题目既保留了系统的文档管理主线，也准确反映了项目使用压缩 NFT 对项目阅读权限进行控制的实现特点，避免把系统写成泛化的“区块链平台”或“数字藏品平台”。

## 仓库证据来源

1. `README.md`：项目定位、部署方式、技术架构、业务功能说明。
2. `package.json`：Nuxt 4、Vue 3、Element Plus、Prisma、Solana 相关依赖版本。
3. `prisma/schema.prisma`：认证、项目集合、文档内容、系统配置、Merkle Tree、压缩 NFT 的核心数据模型。
4. `app/pages/admin/mm/projects/index.vue`：项目管理界面与条件检索、增删改流程。
5. `app/pages/admin/mm/notes/index.vue`：笔记与分类级内容组织流程。
6. `app/pages/project/[id]/home.vue`：前台项目首页展示与鉴权守卫逻辑。
7. `app/pages/project/[id]/v/[versionId]/docs/[noteId].vue`：文档阅读页、分类导航、目录渲染和 Markdown 预览。
8. `server/utils/projectAuthMiddleware.ts`：项目访问权限验证入口。
9. `server/api/project/[id]/verify-access.post.ts`：前台主动鉴权接口。
10. `server/api/admin/solana/cnft/submit.post.ts`：cNFT 铸造交易提交流程、确认逻辑与数据库回写。
11. `server/api/admin/mm/backup/database-export.get.ts`：非认证数据全量备份范围与导出逻辑。

## 源码确认的系统边界

### 已确认实现

1. 管理员初始化、登录、会话校验。
2. 项目、项目版本、分类、笔记、笔记内容版本管理。
3. 前台项目首页和文档阅读页展示。
4. Markdown 内容编辑与预览。
5. 文件上传与文件元数据管理。
6. 系统首页和系统配置管理。
7. 项目访问鉴权开关与基于钱包地址的阅读权限校验。
8. Solana Merkle Tree 管理、压缩 NFT 铸造、交易提交和状态维护。
9. 数据库与文件备份恢复。

### 只可保守表述的内容

1. 性能指标、并发承载能力、链上调用成本的实测结果，源码没有提供完整实验记录，正文只能写设计目标与验证方案。
2. 实际生产环境安全性与长期稳定性，源码可以支撑机制说明，但不能写成经过大规模线上验证。
3. 第三方 RPC 或 DAS 服务的完整运维能力，源码只体现接入方式与错误处理逻辑。
