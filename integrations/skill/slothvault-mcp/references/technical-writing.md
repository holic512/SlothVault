# 技术文章创作教材

本教材用于创作和实质改写技术内容。目标是让指定读者理解问题，并能依据明确的条件验证结论；不是要求每篇文章套用同一模板。

## 1. 先确定文章要解决什么

用一句话写出读者、问题和完成后的结果，例如：“面向已有 Node.js 项目的维护者，解释如何把列表查询与正文详情分离，并通过响应大小对比验证收益。”

教程侧重可执行步骤和预期结果；原理文章侧重因果解释、例子与边界；排错记录侧重症状、证据、定位与修复验证；项目介绍侧重真实功能与可获取材料。短问题可以短答，不强制背景、目录、总结、固定字数或代码块。

开始写作前建立简短证据笔记：重要结论、来源、适用版本、验证状态。它是工作材料，不必原样塞进正文。

## 2. 区分事实、解释和待验证判断

- 实现事实来自实际源码、配置、锁文件和接口声明。记录影响结论的文件或符号，不把猜测写成项目现状。
- 第三方行为查与使用版本匹配的官方资料，遵守当前任务的文档查询规则。不能把最新文档直接当成旧版本证据。
- 运行结论记录命令、环境、输入、输出及检查范围。没有运行条件时写“未运行验证”，不能写“测试通过”。
- 性能结论说明数据规模、对照条件和测量方法。字节减少不直接等于 Token、延迟或成本按同比例降低。
- 未确认的 API、功能、权限、许可证和性能数据不补写为事实。必要时删去结论，或解释缺少何种证据。

修改前：“这个接口速度提升十倍，所有版本都能使用。”

修改后：“列表查询不再读取正文。要量化传输收益，应在同一批文章上比较完整响应字节数；本例尚未测量延迟，也没有验证其他版本。”

有实际测量后，用真实结果替换待测描述，不保留无依据的数字。

## 3. 让说明与代码共同完成解释

先解释触发条件和期望行为，再展示关键代码，并说明为什么有效。每个示例写清运行环境、必要依赖、输入和预期输出。只展示局部代码时，标明插入位置与已有上下文；完整示例应包含必要导入和调用。

修改前：

```python
print(result)
```

修改后（独立 Python 3 示例）：

```python
articles = [{"title": "列表查询", "content": "正文"}]
metadata = [{"title": item["title"]} for item in articles]
print(metadata)
```

根据代码可推导输出为 `[{'title': '列表查询'}]`。这个示例仅解释输出字段选择，不能证明数据库减少了正文读取；数据库查询必须另行核对。如果没有执行示例，应写“预期输出”，而不是“实测输出”。

代码块优先标明语言；伪代码、差异片段、日志和预期输出应标明各自用途。示例不得混用不同版本 API。占位值应说明替换位置，不能伪装成真实凭据。涉及改写数据的命令需说明影响与恢复条件，不能为了验证文章自动执行代码。

## 4. 根据读者缺口补全内容

检查读者是否知道：从哪里开始、必要版本和配置是什么、如何执行、如何观察结果、失败时看哪里、结论在哪些情况下不适用。按文章类型补充这些信息，不为凑章节重复已有内容。

原理解释需要从机制推导结果。教程需要可复现的最短路径。排错文章区分“可能原因”和已定位根因，记录排除依据。不要只罗列概念或把错误日志改写成原因。

图片应服务于当前段落，给出可理解的说明；下载链接说明文件用途。使用已确认的地址，远程链接未检查时不声称有效。本地草稿图片路径在保存前换成实际上传返回路径。

## 5. 去掉重复和没有信息的段落

每段承担一个任务。功能清单已经说明的内容，不再换词放进“项目优势”。先删重复结论，再补缺失的条件、证据或例子。

修改前：“列表接口负责返回文章列表。通过这个接口可以获得文章列表，方便用户管理文章。”

修改后：“列表返回标题、摘要和状态，用于定位文章；读取正文时再调用详情接口。”

跨文章内容复用要结合任务判断；静态脚本只查当前正文中的精确重复长段落，不提供跨库查重或语义抄袭检测。

## 6. 检查并交付

运行文章流程中的可选静态脚本，检查 Markdown 中可确定的问题。它覆盖普通 ATX/Setext 标题、围栏和普通段落，不是完整 CommonMark 解析器；嵌套列表、HTML 和复杂链接应人工检查。合法的省略写法或刻意示例可能触发提示，按上下文判断，不机械改写。

最后按实际文章检查：

- 重要技术结论是否有证据，版本和条件是否一致？
- 示例的导入、输入、执行位置和预期结果是否足够，验证状态是否真实？
- 标题是否准确，段落是否推动解释，重复内容是否可以删除？
- 必要步骤、失败处理、图片及链接是否完整？
- 保存的是正确文章和字段，发布是否属于当前授权？

报告已执行的检查及仍未验证的部分。脚本无错误仅代表没有发现其规则覆盖的问题，不代表文章必然正确；模型质量与人工判断不由脚本评分替代。
